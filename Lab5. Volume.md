
# Отчёт о выполнении задания с использованием Docker, Nginx и Volume

В данном отчете описан процесс создания и настройки контейнера с Nginx, а также использования volume для хранения данных (в данном случае веб-страниц и конфигурационных файлов).

## Шаг 1: Запуск контейнера с Nginx

1. Для начала был запущен контейнер с образом `nginx`:

   ```
   docker run -d -p 8080:80 --name nginx-container nginx
   ```

   - Параметр `-d` — запуск контейнера в фоновом режиме.
   - Параметр `-p 8080:80` — проксирование порта 8080 на хосте к порту 80 внутри контейнера.
   - `--name nginx-container` — имя контейнера.
   - `nginx` — официальный образ Nginx.

2. Для проверки работы контейнера использована команда:

   ```
   docker ps
   ```

   Контейнер запущен и слушает порт 8080 на хосте.

3. Проверка доступности веб-страницы Nginx с использованием браузера:

   Открыли браузер и перешли по адресу:

   ```
   http://localhost:8080
   ```

   На экране появилась стандартная стартовая страница Nginx.

## Шаг 2: Использование Volume для Nginx

1. Для хранения данных и конфигурации использован volume, который монтируется в директорию `/usr/share/nginx/html` внутри контейнера. Это позволяет сохранять изменения, например, в файле `index.html`, даже после перезапуска контейнера.

   В Dockerfile был указан volume:

   ```dockerfile
   VOLUME /usr/share/nginx/html
   ```

2. При запуске контейнера использован параметр `-v` для монтирования volume:

   ```
   docker run -d -p 8080:80 -v nginx-html:/usr/share/nginx/html --name nginx-with-volume nginx
   ```

   - Параметр `-v nginx-html:/usr/share/nginx/html` указывает Docker создать volume под названием `nginx-html`, который будет монтироваться в директорию `/usr/share/nginx/html` контейнера.
   - Это позволяет сохранять все изменения, сделанные в файле `index.html`, даже после перезапуска контейнера.

## Шаг 3: Копирование конфигурационного файла в контейнер

1. Был создан конфигурационный файл Nginx (`default.conf`) с минимальной настройкой:

   ```nginx
   server {
       listen 80;
       server_name localhost;

       location / {
           root /usr/share/nginx/html;
           index index.html;
       }
   }
   ```

2. Для копирования конфигурации в контейнер использована команда:

   ```
   docker copy default.conf nginx-container:/etc/nginx/conf.d/default.conf
   ```

   Это позволило внедрить новую конфигурацию в контейнер.

3. После копирования конфигурации был перезапущен контейнер для применения изменений:

   ```
   docker restart nginx-container
   ```

## Шаг 4: Изменение стартовой страницы

1. Был создан новый файл `index.html` с измененным содержимым:

   ```html
   <html>
   <head>
       <title>Новый контент</title>
   </head>
   <body>
       <h1>Новый контент на странице!</h1>
   </body>
   </html>
   ```

2. Для копирования файла `index.html` в контейнер была использована команда:

   ```
   docker copy index.html nginx-container:/usr/share/nginx/html/index.html
   ```

   Это позволило заменить стартовую страницу на новую.

## Шаг 5: Проверка работы с помощью `curl`

1. Для проверки работы контейнера с новой конфигурацией и страницей была использована команда `curl`:

   ```
   curl http://localhost:8080
   ```

2. В результате был получен следующий вывод:

   ```html
   <html>
   <head>
       <title>Новый контент</title>
   </head>
   <body>
       <h1>Новый контент на странице!</h1>
   </body>
   </html>
   ```

   Это подтверждает, что контейнер работает с новой конфигурацией и обновленной страницей.

3. Изменили конфигурационный файл Nginx.
4. Обновили стартовую страницу контейнера.
5. Проверили работоспособность через команду `curl`.

Контейнер теперь работает с новой конфигурацией и страницей, и проверка с помощью `curl` подтвердила правильность работы.
